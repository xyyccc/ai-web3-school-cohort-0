## Handbook Reading: Agent Wallet（智能体钱包）

**来源**: https://aiweb3.school/zh/handbook/bridge/agent-wallet/
**字数**: 约 3555 字 / 12 分钟

### 核心定义

Agent Wallet 不是"给 AI 一个钱包私钥"这么简单。真正要解决的问题是：Agent 可以代表用户做哪些链上动作，这些动作有没有额度、时间、对象和风险限制，用户什么时候必须重新确认。

### 第一性原理（First Principle）

> 控制权不能交给一个概率系统。Agent 只能拿到可验证、可限制、可撤销的行动空间。

三条推论：
1. Agent 不直接控制主资产：可以生成计划和交易草稿，但不应拿到用户主私钥
2. 钱包不只是签名按钮，而是权限系统：时间、金额、合约、方法、资产、接收方和撤销条件
3. 自动化必须绑定撤销能力：用户随时能看见 Agent 拿了什么权限、做过什么、还能做什么、在哪关闭

### 9 个知识节点（Knowledge Nodes）

| # | 节点 | 难度 | 核心 |
|---|------|------|------|
| 1 | AA Wallet | 中级 | Account Abstraction 让账户表达规则，而不只是私钥控制；Agent 场景下账户终于可以表达"谁能操作、能操作什么、什么时候失效" |
| 2 | Smart Account | 中级 | 带规则的合约钱包：谁可发起、哪些需确认、哪些合约可调用、每天花多少、何时失效、异常如何暂停 |
| 3 | Safe | 中级 | 多签和智能账户基础设施；Agent 生成交易草稿，大额仍需要多签确认；Agent 参与流程而非独占控制权 |
| 4 | Session Key | 高级 | 临时、有限权限的小钥匙：有效时间、可调合约、单笔/总额度、资产类型、是否可转出外部、是否可撤销 |
| 5 | Policy | 高级 | 把"Agent 可以做什么"写成系统可检查的规则：每日额度、白名单合约、滑点限制、NFT 必须人工确认等 |
| 6 | Guard | 高级 | 确定性拦截层：在交易发出前用确定性规则拒绝越界动作；Agent 负责生成，Guard 负责拒绝 |
| 7 | Simulation | 中级 | 签名前预演交易结果：付多少、收什么、哪些授权改变、哪个合约被调用、失败成本、是否与用户目标一致 |
| 8 | Revocation | 中级 | 权限撤销：不只是用户手动撤回，系统也要在 session key 到期、额度用完、多次失败、异常地址时自动收紧 |
| 9 | Human Check | 初级 | 分层确认：低风险自动 → 中风险模拟后确认 → 高风险明确展示+确认 → 越界直接拒绝，不显示为"确认"选项 |

### 理想执行链路

```
用户目标+约束 → Agent 读上下文+生成计划 → 系统转受限交易
    → Guard+Simulation 检查 → 用户确认关键动作
    → Smart Account/Safe 执行 → 日志记录
```

最容易出问题的在第 3-6 步：很多项目"模型生成计划"做得很顺，但没有认真处理交易模拟、权限校验、撤销入口和审计记录。

### 最小实践：Agent 受限支付钱包

场景：用户允许 Agent 在一天内最多花 5 USDC，支付白名单 API/工具服务。Agent 可自动小额支付，但不能转给任意地址或修改授权。

需实现/写清：
1. 授权额度、时间、目标地址
2. Agent 可自动执行的操作
3. 哪些必须人工确认
4. 交易发出前如何模拟和展示
5. 超出 policy 时系统拒绝
6. 用户在哪查看和撤销权限
7. 每次支付的审计记录

演示四个 case：
- ✅ 正常：额度内自动支付+记录
- ❌ 超限：6 USDC 被 policy 拒绝
- ❌ 异常：非白名单地址被 Guard 拦截
- 🔒 撤销：用户手动关掉 session key

## 四个章节的完整关系（Four Chapters Integration）

```
Chain-aware Context ──→ 提供链上事实（输入层）
Web3 Tool Use     ──→ 提供读写链能力（能力层）
Agent Workflow    ──→ 组织可控执行流程（流程层）
Agent Wallet      ──→ 定义权限边界和安全（权限层）
```

四层缺一不可：
- 没有 Context：Agent 在错误信息上做决定
- 没有 Tool Use：Agent 只能聊不能做
- 没有 Workflow：执行流程不可控
- 没有 Wallet：权限边界模糊，资产风险不可控

## Key Takeaways（关键收获）

1. **Agent Wallet 的核心矛盾**：执行能力 vs 安全边界。不是让 AI 完全接管资产，也不是让它什么都不能做，而是让用户把一小部分、可撤销、可审计的权限交给 Agent。
2. **产品设计原则**：所有自动化权限，都应有一个用户看得见的关闭入口。模糊的"允许自动操作"不适用于链上资产。
3. **Session Key 不是小号私钥，是一组受限能力**。必须限制时间、额度、目标合约、资产类型。
4. **分工清晰**：Agent 生成候选动作，Guard 拒绝越界动作，Simulation 预演结果，Human 确认关键决策。
5. 从产品视角看，Agent Wallet 的好坏标准不是"有多自动化"，而是**用户能不能清楚地知道 Agent 拿了什么权限、做过什么、还能做什么、怎么关掉**。
