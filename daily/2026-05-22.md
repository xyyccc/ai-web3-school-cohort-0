### 1. Chain-aware Context（链感知上下文）

**来源**: https://aiweb3.school/zh/handbook/bridge/chain-aware-context/

**核心定义**: 让 AI 在回答或行动前，能看见正确的链（chain）、地址（address）、合约（contract）、交易（transaction）、事件（event）、余额（balance）、授权（authorization）和数据来源（data source），而不是只靠用户一句话猜测链上状态。

**第一性原理（First Principle）**: 模型不能凭语言记忆判断链上事实，链上事实必须从工具和索引层读取。

**7 个知识节点（Knowledge Nodes）**:

| 节点 | 难度 | 要点 |
|------|------|------|
| On-chain Data | 初级 | 读取时需附带 chain id、block number、contract address、method、返回值、读取时间 |
| Contract Docs | 初级 | ABI 只给函数签名，文档补足业务语义；但文档可能过期，需链上数据验证 |
| ABI / Event | 中级 | ABI 让工具知道如何编码调用；Event 是合约的业务日志（Transfer、Swap、Deposit 等） |
| Transaction History | 中级 | 理解用户/合约过去做过什么；不能只看自然语言总结，必须保留 tx hash、block number 等 |
| Explorer Context | 初级 | 区块浏览器提供可检查入口；给 explorer link 比只说"交易成功"更可靠 |
| Indexing Context | 中级 | 把链上事件整理成面向产品的查询数据；必须带时间戳和同步状态 |
| Citation | 初级 | 每个关键结论附上链上证据（tx hash、block number、contract address、explorer link） |

**高质量上下文包应收录**: 用户目标、chain id、用户地址和余额、合约地址和 ABI、文档和风险提示、最近交易和授权、索引更新时间、每条结论的 citation。

### 2. Web3 Tool Use（Web3 工具调用）

**来源**: https://aiweb3.school/zh/handbook/bridge/web3-tool-use/

**核心定义**: 将 Web3 的 RPC、合约读写、交易生成、钱包确认、区块浏览器和 DeFi 操作封装为 AI Agent 可调用的工具。

**第一性原理**: 模型可以选择工具，但工具必须用确定性边界限制模型。不要让 Agent 直接拼接任意 calldata 或调用任意地址。

**8 个核心工具**:

| 工具 | 难度 | 安全要点 |
|------|------|---------|
| RPC Tool | 初级 | 读写分离：只读开放较宽，写入单独拆分 |
| Contract Read | 初级 | 读错网络=错误事实，导致 Agent 错误建议 |
| Contract Write | 高级 | 必须模拟+权限+确认；限制在白名单合约和方法内 |
| Wallet Tool | 高级 | 连接/签名/发送/授权/撤销分拆；不能绕过钱包确认 |
| Explorer Tool | 初级 | 提供可验证证据：交易是否成功、合约是否 verified |
| DeFi Tool | 高级 | 协议白名单+最大交易额+最大滑点+人工确认 |
| Tool Permission | 高级 | 按工具/合约/方法/金额/时间/频率分层：查询自动，大额人工确认 |
| Tool Log | 中级 | 每次调用记录输入/输出/时间/chain id/tx hash/确认人 |

**权限分层示例**: 查询余额自动允许 → 生成交易草稿自动允许 → 小额白名单支付 session key 允许 → 大额转账人工确认 → 任意合约调用默认禁止。

### 3. Agent Workflow（智能体工作流）

**来源**: https://aiweb3.school/zh/handbook/bridge/agent-workflow/

**核心定义**: 把"用户目标 → 上下文读取 → 计划生成 → 工具调用 → 风险检查 → 执行 → 记录与复盘"组织成可控流程。

**第一性原理**: 高风险 Agent 不能只有"下一步推理"，必须有状态、边界和停止条件。流程要显式，不能将所有执行逻辑藏在一段长 prompt 里。

**7 个知识节点**:

| 节点 | 难度 | 要点 |
|------|------|------|
| Task Graph | 中级 | 把目标拆成节点和依赖，每步设输入/输出/权限/停止条件 |
| State Machine | 高级 | 状态如 draft → context_loaded → plan_ready → waiting_user_confirmation → submitted → confirmed |
| Human-in-the-Loop | 中级 | 只在高风险点引入人工确认；只读自动，高风险人工，越权直接拒绝 |
| Retry / Fallback | 中级 | 不能盲目重试；pending 不重复发；RPC 异常可切换 provider 但要记录来源 |
| Trace | 初级 | 记录用户目标、模型版本、上下文来源、工具输入输出、策略判断、tx hash、最终状态 |
| Evaluation Harness | 高级 | 测试：是否正确拒绝越权、是否识别错误链、缺少数据时是否停止 |
| Regression Set | 中级 | 固定测试用例：正常 swap、错误链、无限 approve、余额不足、用户拒绝签名等 |

## 三个章节的关系 (How the Three Chapters Fit Together)

```
Chain-aware Context（输入层）
    ↓ 提供链上事实
Web3 Tool Use（能力层）
    ↓ 提供读链、写链、签名能力
Agent Workflow（流程层）
    ↓ 把事实+能力组装成安全可控的执行路径
Agent Wallet（权限层，后续学习）
```

**核心理解**: 没有 Chain-aware Context，Tool Use 和 Workflow 都建立在不可靠的上下文上。有了上下文 + 工具 + 工作流，Agent 才能从"解释链上信息"走到"参与链上执行"。

---

## Key Takeaways (关键收获)

1. AI × Web3 不是让 AI 直接调合约（那很危险），而是建立三层：**事实层（上下文） → 能力层（工具） → 流程层（工作流）**。
2. 每一层都有各自的安全边界：上下文要带 citation（引用）、工具要分离读写权限、工作流要有 human-in-the-loop（人在回路）。
3. 产品视角：一个好的 AI × Web3 产品 = 链感知上下文包 + 受限工具集 + 显式工作流 + 可审计日志。缺任何一个，都只是 demo，不是产品。
4. 第一性原理反复强调的核心：**不要信任模型的记忆，一切链上事实必须从工具读取并附带来源（citation）**。
